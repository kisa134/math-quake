## 1. Разделение ответственности (кто что считает)

```
                ┌─────────────────────────── SERVER (authoritative) ───────────────────────────┐
                │  • high-level состояние существа: root transform, velocity, state, hp        │
                │  • GAIT GENOME (эволюционируемый вектор параметров) — ЕДИНЫЙ источник правды   │
                │  • AI FSM: куда идти (wander / seek / chase / flee / stagger / dead)          │
                │  • GA loop (headless, фоновый бюджет): fitness → selection → next genome       │
                │  • пишет всё это в world_snapshot @ ~15 Гц                                    │
                └───────────────────────────────────┬──────────────────────────────────────────┘
                                                    │ world_snapshot (genome + root + state)
                                                    ▼
                ┌─────────────────────────── CLIENT (cosmetic sim) ────────────────────────────┐
                │  • интерполирует root transform между снапшотами                             │
                │  • ЛОКАЛЬНО крутит PD-контроллеры конечностей из genome (game/locomotion.ts)  │
                │  • конечности = косметика: НИКОГДА не синкаются (как debris/ragdoll)          │
                │  • death → ragdoll PASSIVE (limp)                                             │
                └──────────────────────────────────────────────────────────────────────────────┘
```

**Инвариант синка (важно для дешевизны и детерминизма):** по сети едут **только** `root` (позиция+yaw), `vel`, `state`, `hp`, `genomeId`/`genome`. **Углы суставов, фазы шага, крутящие моменты — не едут никогда.** Два клиента могут показать чуть разные позы ног в один и тот же момент — это допустимо ровно так же, как разлёт debris в §02. Синхронизирована «душа» (куда и как задан ход), а не «мясо» (конкретный угол колена).

**Почему genome, а не поза:** genome — это ~16 float. Поза бипеда — 6–10 углов × N существ × кадр. Гоняя genome раз в снапшот, мы синкаем «стиль ходьбы» за копейки, а дорогую PD-анимацию считает каждый клиент сам, LOD-ом отбраковывая далёких.

## 2. Active-ragdoll локомоция — контроллер

### 2.1 Идея

Тело существа — это rapier rigidbodies, соединённые суставами (из инкр. 10). Мы **не** ставим позу кинематически. Вместо этого каждый кадр PD-контроллер задаёт каждому суставу **целевой угол** `targetAngle(phase, genome)` и жёсткость `stiffness`, а физика сама доводит сустав до цели через мотор. Возникающие реакции опоры о землю толкают тело вперёд — **походка эмерджентна**, и потому шатание от толчка выглядит «живым»: контроллер продолжает тянуть к цели, физика сопротивляется, тело качается и восстанавливается.

Две связки:
1. **GAIT ENGINE** — фазовый генератор целевых углов (CPG-подобный, central pattern generator в простейшем синусоидальном виде).
2. **BALANCE** — держит торс вертикально и центр масс над опорой, чтобы бипед не падал.

### 2.2 Фазовый генератор шага (CPG)

Одна глобальная фаза `φ ∈ [0, 2π)`, растёт со временем:

```
φ(t+dt) = (φ(t) + 2π · freq · dt) mod 2π
```

Для каждого сустава `j` целевой угол:

```
targetAngle_j(φ) = center_j + amp_j · sin(φ + phaseOffset_j)
```

- `center_j` — угол «стойки» сустава (нейтраль);
- `amp_j` — амплитуда качания (радианы);
- `phaseOffset_j` — сдвиг фазы (даёт координацию: правая нога в противофазе к левой = `+π`, колено отстаёт от бедра и т.п.).

**Биуед (biped) — карта суставов и seed-значения** (это и есть «hand-tuned seed genome», ходит на 1-м кадре):

| JointId | center (рад) | amp (рад) | phaseOffset | gain (stiffness) |
|---|---|---|---|---|
| `hipL` | −0.05 | 0.55 | 0.0 | 14 |
| `kneeL` | 0.35 | 0.70 | +1.6 | 10 |
| `ankleL`| 0.0 | 0.30 | +2.4 | 6 |
| `hipR` | −0.05 | 0.55 | +π | 14 |
| `kneeR` | 0.35 | 0.70 | +π+1.6 | 10 |
| `ankleR`| 0.0 | 0.30 | +π+2.4 | 6 |
| `spine` | 0.08 (lean) | 0.05 | 0.0 | 22 |
| `armL`/`armR` | 0.0 | 0.35 | противофаза к одноимённой ноге | 4 |

Правая половина = левая, сдвинутая на `π` → классический альтернирующий шаг. Колено отстаёт от бедра (`+1.6`) → нога подгибается в переносе и распрямляется в опоре. Небольшой `lean` торса вперёд конвертирует «топтание на месте» в движение вперёд.

> **Почему это уже ходит:** синусный CPG с противофазными ногами + слегка наклонённый торс + PD-баланс — это минимальный рабочий рецепт двуногой ходьбы для игр (тот же приниип, что в active-ragdoll демо вроде QWOP-корректных контроллеров и Rapier/Bullet motor-walkers). Seed выше подобран «на глаз инженера» и должен ходить медленно, но устойчиво; GA потом ускорит и сгладит.

### 2.3 PD-привод к цели

`driveJoint` из инкр. 10 уже инкапсулирует PD внутри мотора (angular spring к `targetAngle` с `stiffness`, damping — внутри рига). Наш контроллер только считает цель и жёсткость:

```ts
for (const j of rig.joints) {
  const g = genome.joint[j.id];
  const target = g.center + g.amp * Math.sin(phase + g.phaseOffset);
  rig.driveJoint(j.id, target, g.gain * globalStiffness);
}
```

`globalStiffness ∈ [0..1]` — общий множитель: 1.0 при ходьбе, снижается в `stagger`, → 0 в `dead` (плавный переход в limp, §4).

Если 10 отдаёт «сырой» мотор без встроенного PD — адаптер в §5.1 считает момент `τ = kp·(target−angle) − kd·angVel` руками.

### 2.4 Баланс — «virtual model» (spring-to-upright)

Самая хрупкая часть. Берём **простую и робастную** стратегию из трёх дешёвых составляющих (без полноценного inverse-dynamics):

1. **Torso upright torque.** Каждый кадр меряем наклон торса от вертикали и прикладываем **корректирующий момент к корневому телу торса**, тянущий его к вертикали (виртуальная угловая пружина):
   ```
   tiltErr = angleBetween(torsoUp, worldUp)          // 0 = идеально вертикально
   axis    = normalize(cross(torsoUp, worldUp))
   torque  = axis · (Kp_balance · tiltErr − Kd_balance · torsoAngVel)
   torso.applyTorqueImpulse(torque · dt)
   ```
   `Kp_balance`, `Kd_balance` — в геноме (эволюционируют). Это «невидимая рука», не даёт упасть, но не отменяет физику толчков.

2. **CoM-over-support (foot placement bias).** Считаем горизонтальный сдвиг центра масс относительно средней точки стоп. Подмешиваем этот сдвиг в `center` бёдер (шаг ставится «под падение» — capture-point-lite):
   ```
   comErr = horiz(CoM) − horiz(midFoot)
   hip.center += stepBias · dot(comErr, forward)   // шагаем шире в сторону падения
   ```
   `stepBias` — в геноме. Это и есть механизм, из-за которого от толчка существо **делает шаг в сторону толчка и ловит себя** — ключ к «живому» ощущению.

3. **Heading torque.** Мягкий момент по yaw, доворачивающий существо к `desiredHeading` (из AI, §3). Слабый, чтобы не превратить в танк на гусеницах:
   ```
   yawErr = angleWrap(desiredYaw − currentYaw)
   torso.applyTorqueImpulse(worldUp · Kp_yaw · yawErr · dt)
   ```

**Реакция на толчок = эмерджентность.** Когда игрок стреляет/пинает существо (impulse в rapier), торс кренится → (1) тянет назад к вертикали, (2) CoM уходит за опору → бёдра ставят шаг в сторону падения, (3) CPG продолжает крутиться. Итог: спотыкнулся, шагнул, поймал баланс (или упал, если толчок сильный) — без единой строки «анимации падения».

### 2.5 Fall-recovery (детект и восстановление)

- **Fall detect:** `torsoUp·worldUp < cos(60°)` **и** высота торса ниже порога дольше `fallGraceMs (350)` → состояние `staggered`. Если ниже `cos(85°)` дольше `1200ms` → `downed`.
- **`staggered`:** `globalStiffness` временно ↑ (жёстче ловим), CPG freeze на полшага, усиленный `stepBias`. Часто ловит себя — это и выглядит живо.
- **`downed`:** запускаем **get-up скрипт** — заранее зашитая короткая последовательность целевых углов (подтянуть ноги под себя → распрямить → поднять торс), проигрывается 0.8–1.2 с, затем возврат в `walk`. Get-up-скрипт **не эволюционирует** (детерминированный, чтобы не плодить jank).
- Если существо «мертво» (hp≤0) — никакого get-up: сразу PASSIVE limp (§4).

## 3. AI-состояния НАД локомоцией

Локомоция = «**как** двигаться». AI = «**куда**». AI выдаёт локомоции только `desiredHeading` и `moveGate ∈ {stop, walk, run}` (run ⇒ ↑ `freq`, `amp`). FSM на сервере:

```
      spawn → WANDER ──(игрок в радиусе aggro)── CHASE ──(в упор)── ATTACK
                 ▲                                  │                  │
                 └──────(потерял цель, таймаут)─────┘                  │
   любое ── (сильный impulse / получил урон) → STAGGERED → (встал) → предыдущее
   hp≤0 → DEAD (ragdoll limp, локомоция off)
```

| State | desiredHeading | moveGate | Заметки |
|---|---|---|---|
| WANDER | случайная точка/периметр | walk | бродит, оживляет сцену |
| CHASE | к игроку (`atan2` в плоскости XZ) | run | как текущий `applyImpulse`-к-камере, но через ноги |
| ATTACK | к игроку | stop | стреляет (перенести из `Enemies.tsx` стр.68–78) |
| FLEE | от игрока (low hp) | run | опционально |
| STAGGERED | freeze | stop | §2.5 |
| DEAD | — | off | §4 |

**Важно:** `desiredHeading` меняет только цель баланса/CPG; **скорость по земле — следствие физики шага**, не задаётся напрямую. Быстрее геном ходит — быстрее существо. Это и есть смысл «научилось двигаться».

## 4. Переход locomotion ↔ limp (смерть)

Строго через режимы рига инкр. 10:

```ts
// жив, идёт:
rig.setMode('active');  locomotion.tick(rig, genome, ai, dt);

// момент смерти (hp≤0):
rig.setMode('passive');           // все моторы off → тряпка
rig.applyDeathImpulse(lastHitDir); // необяз.: добросить в сторону выстрела
// далее конечности падают физикой; интеграция с debris/DeathFx §02 остаётся
```

Плавность: за 150 мс перед `passive` линейно гасим `globalStiffness → 0` (мышцы «отпускает»), чтобы не было щелчка от резкого отключения моторов. Существо оседает, а не выключается кадром.

Респавн: `passive → active`, `phase=0`, genome = текущий best-known (§8).

## 5. Модуль `src/game/locomotion.ts` — API

Чистый модуль в духе `movement.ts`: без аллокаций в горячем пути (переиспользуемые `_vec`, `_quat` на модульном уровне), вся математика — pure, вызывающий владеет ригом и стором.

```ts
import type { Rig, JointId } from './ragdoll';   // из инкремента 10

// ── Геном походки: то, что эволюционирует и едет в снапшоте ──
export interface JointGene {
  center: number;      // рад, нейтральный угол
  amp: number;         // рад, амплитуда качания
  phaseOffset: number; // рад
  gain: number;        // множитель stiffness сустава
}
export interface GaitGenome {
  freq: number;              // Гц, частота шага
  lean: number;              // рад, наклон торса вперёд
  stepBias: number;          // capture-point усиление
  KpBalance: number;
  KdBalance: number;
  KpYaw: number;
  joint: Record<JointId, JointGene>;
}

// ── Вход от AI (сервер → снапшот → клиент) ──
export interface LocoDrive {
  desiredYaw: number;
  moveGate: 'stop' | 'walk' | 'run';
}

// ── Персистентное состояние контроллера на клиенте (по одному на существо) ──
export interface LocoState {
  phase: number;
  globalStiffness: number;
  fallTimer: number;
  posture: 'walk' | 'staggered' | 'downed' | 'getup' | 'dead';
  getupT: number;
}

export function makeLocoState(): LocoState;

/** Хэнд-тюненный seed — гарантированно ходит на 1-м кадре. */
export const SEED_BIPED: GaitGenome;
export const SEED_QUADRUPED: GaitGenome;  // LATER (§10)
export const SEED_BLOB: GaitGenome;       // LATER (§10)

/** Границы гена для GA (clamp + init) — см. таблицу §7. */
export const GENE_BOUNDS: Record<keyof GaitGenome | string, [number, number]>;

/**
 * Один кадр активной локомоции. Мутирует rig (через driveJoint/applyTorque)
 * и loco (phase/posture). Возвращает измеренные метрики для fitness-сэмплинга.
 */
export function tickLocomotion(
  rig: Rig,
  genome: GaitGenome,
  drive: LocoDrive,
  loco: LocoState,
  dt: number,
): LocoSample;   // { forwardSpeed, tilt, footContacts, energy }

/** Дешёвая процедурная поза для дальнего LOD (без физики суставов). §8.2 */
export function tickProceduralPose(rig: Rig, genome: GaitGenome, loco: LocoState, dt: number): void;

/** Плавно гасит моторы и уводит в limp. */
export function enterLimp(rig: Rig, loco: LocoState): void;
```

### 5.1 Адаптер, если у 10 «сырой» мотор

```ts
// Если ragdoll.driveJoint отсутствует / принимает момент, а не (target,stiffness):
function pdTorque(angle: number, angVel: number, target: number, kp: number, kd: number) {
  return kp * (target - angle) - kd * angVel;   // классический PD
}
// затем rig.setJointTorque(id, clamp(pdTorque(...), -TAU_MAX, TAU_MAX))
```
`TAU_MAX` (кламп момента) обязателен: не даёт GA «взорвать» суставы нефизичной силой.

## 6. Сеть: снапшот и серверные добавки

### 6.1 Добавки в `world_snapshot` (инкр. 05 несёт формат, 11 добавляет поля существ)

```ts
interface CreatureSnap {
  id: string;
  type: 'biped' | 'quadruped' | 'blob';
  root: [number, number, number];   // позиция торса
  yaw: number;
  vel: [number, number, number];
  state: 'wander'|'chase'|'attack'|'flee'|'staggered'|'downed'|'dead';
  hp: number;
  genomeId: number;                  // ссылка на активный геном в реестре species
  genomeRev: number;                 // ++ когда GA сменил геном → клиент перечитывает
}
interface WorldSnapshot {
  t: number;
  creatures: CreatureSnap[];
  // + genomes: отдельным редким каналом (см. 6.2), НЕ в каждом кадре
}
```

- Снапшот @ **~15 Гц** (root/yaw/state/hp). Клиент интерполирует `root` между снапшотами (как RemotePlayers).
- **Геном едет отдельно и редко** — `creature_genome` эмитится только когда GA присвоил новый (по `genomeRev`), а не 15 раз в секунду. Полный `GaitGenome` ≈ 16 float+8 суставов×4 ≈ ~48 float — дёшево при частоте «раз в поколение».

### 6.2 Каналы socket.io (добавить в `server.ts` / `socket.ts`)

| Событие | Направление | Payload | Когда |
|---|---|---|---|
| `world_snapshot` | S→C | `WorldSnapshot` (root/yaw/state/hp) | 15 Гц |
| `creature_genome` | S→C | `{ id, genome, genomeRev }` | при смене генома (редко) |
| `creature_hit` | C→S | `{ id, damage, dir }` | клиент попал (сервер валидирует hp) |
| `creature_impulse` | C→S→C | `{ id, impulse }` | толчок (для реакции; сервер релеит для косметики) |

Урон/hp остаются **авторитетно на сервере** (как уже сделано для игроков в `server.ts` стр.71–98) — клиент шлёт `creature_hit`, сервер списывает hp и рассылает в снапшоте.

## 7. Геном: кодировка, диапазоны, тюнинг-таблица

Геном = плоский float-вектор (для GA-операторов) + view-обёртка `GaitGenome`. Плоская длина для биуеда: `6 глобальных + 8 суставов × 4 = 38 генов`.

| Ген | Диапазон | Seed (biped) | Смысл / эффект |
|---|---|---|---|
| `freq` | 0.6 … 3.2 Гц | 1.4 | темп шага; выше → быстрее и рискованнее |
| `lean` | −0.05 … 0.30 | 0.08 | наклон вперёд = скорость; много → падение |
| `stepBias` | 0.0 … 0.9 | 0.35 | ловля баланса шагом; ключ к «живучести» |
| `KpBalance` | 4 … 40 | 18 | жёсткость выпрямления торса |
| `KdBalance` | 0.5 … 8 | 3 | демпфер (без него — колебания) |

| `joint.*.center` | −0.6 … 0.6 | таб. §2.2 | нейтральный угол |
| `joint.*.amp` | 0.0 … 1.2 | таб. §2.2 | амплитуда качания |

## 8. Генетический алгоритм — `src/game/ga.ts`

### 8.1 Где и как крутится (не стопорит тик)

Два режима эволюции, оба на сервере, **headless**:

- **A. Live-fitness (основной, дешёвый, всегда on).** Мы не гоняем отдельный симулятор — мы **измеряем реальных живущих существ**. Каждое существо носит активный геном и накапливает fitness-сэмплы (пройденная дистанция, падения, энергия) окном `EVAL_WINDOW = 12 c`. По истечении окна геном получает итоговый fitness, идёт в пул поколения своего species, существу выдаётся следующий геном-кандидат. Стоимость ≈ ноль сверх обычного тика (метрики и так считаются).
- **B. Background micro-sim (опц., для скорости эволюции).** Один облегчённый rapier-мир на сервере, где `SIM_BUDGET_MS = 2 мс/тик` тратится на «проигрывание» 1–2 кандидатов ускоренно (fixed-step, без рендера, LOD-физика). Строго ограничено бюджетом: `while(now()-t0 < SIM_BUDGET_MS) stepCandidate()`. Никогда не блокирует игровой тик — что не досчитали в этот тик, досчитаем в следующий.

MVP использует **только A** (проще, детерминизм не нужен, владелец буквально видит, как живые существа хорошеют). B — ускоритель на потом.

### 8.2 Параметры GA (конкретно)

| Параметр | Значение | Обоснование |
|---|---|---|
| Популяция на species | `POP = 24` | достаточно для разнообразия, дёшево держать |
| Кодировка | float-вектор 38 генов | §7 |
| Fitness-окно | `EVAL_WINDOW = 12 c` | хватает пройти дистанцию и показать стабильность |
| Селекция | **турнир k=3** + **элитизм 2** | 2 лучших переходят без изменений (не теряем ходока) |
| Кроссовер | **BLX-α, α=0.5**, `pCross = 0.75` | смешивает родителей по-геномно, гладко для float |
| Мутация | гаусс `σ = 8 %` диапазона гена, `pMut = 0.12` на ген | мягкие толчки; не ломает рабочую походку |
| Поколение | когда ≥`POP` геномов оценены (по live-fitness ≈ каждые `POP·EVAL_WINDOW / активных_существ`) | адаптивная каденция |
| Поколений за сессию | не ограничено; персист best (§8.4) | владелец видит прогресс |
| Seed поколения 0 | `SEED_BIPED` + 23 его мутанта (σ=15%) | frame-1 ходит, эволюция от рабочей точки |

> **Каденция на пальцах:** при 10 активных существах и окне 12 с новое поколение (24 оценки) собирается примерно каждые `24·12/10 ≈ 29 c`. За 5 минут сессии — ~10 поколений: достаточно, чтобы разница «до/после» была видна глазом.

### 8.3 Fitness-формула

```
fitness =  w_dist   * forwardDistance          // главное: уехал вперёд по desiredHeading
         - w_fall   * fallCount                 // падал/лёг — штраф
         - w_tilt   * meanTilt                  // дрожал/кренился — штраф за нестабильность
         - w_energy * totalTorqueWork           // жёг момент зря — штраф (гладкость)
         - w_wobble * headingDrift              // ушёл не туда — штраф
```

Веса (стартовые): `w_dist=1.0, w_fall=6.0, w_tilt=1.5, w_energy=0.02, w_wobble=0.8`.
- `forwardDistance` — проекция пройденного пути на `desiredHeading` за окно (не «наездил кругами»).
- `fallCount` — сколько раз входил в `downed`.
- `meanTilt` — средний `tiltErr` (нестабильность).
- `totalTorqueWork ≈ Σ|τ·Δangle|` — энергия (наказывает судорожные, «нездоровые» походки → GA любит плавные, «живые»).

Штраф за падение доминирует → эволюция сперва учится **не падать**, потом **идти быстрее** — ровно та кривая, которую владелец хочет наблюдать.

### 8.4 Персист лучших

```ts
// server-side, in-memory + плоский JSON рядом с сервером
bestGenomes: Record<Species, { genome: GaitGenome; fitness: number; gen: number }>
```

- Новое существо спавнится с `bestGenomes[species]` (эксплуатация) **или** с мутантом best (`σ=15%`, вероятность `EXPLORE = 0.3`) — исследование продолжается.
- Сохранять `best` на диск (`bestGenomes.json`) на смену поколения → между сессиями существа **стартуют уже обученными**. Владелец возвращается — они уже ходят лучше, чем вчера.
- Стартовый файл-сид можно закоммитить, чтобы первый запуск был уже приличным.

### 8.5 `src/game/ga.ts` — API

```ts
export interface Individual { genome: GaitGenome; fitness: number | null; }
export interface Population { species: Species; gen: number; pool: Individual[]; }

export function seedPopulation(species: Species, size?: number): Population;   // seed + мутанты
export function nextGenome(pop: Population): { genome: GaitGenome; token: number };  // выдать кандидата
export function reportFitness(pop: Population, token: number, fitness: number): void; // вернуть оценку
export function evolveIfReady(pop: Population): boolean;   // если все оценены → новое поколение (турнир+элита+кросс+мут)
export function bestOf(pop: Population): Individual;

// операторы (pure, тестируемые):
export function tournament(pool: Individual[], k: number): Individual;
export function blxCrossover(a: GaitGenome, b: GaitGenome, alpha: number): GaitGenome;
export function mutate(g: GaitGenome, sigmaFrac: number, pMut: number): GaitGenome; // + clamp к GENE_BOUNDS
```

Операторы работают над плоским вектором; `GaitGenome ↔ number[]` через `flatten()/unflatten()`.

## 9. Интеграция и MVP

### 9.1 Порядок интеграции

1. **(10)** `ragdoll.ts` даёт biped-риг + `driveJoint` + passive/active. Проверить `driveJoint` вручную (задать статичный target → сустав держит угол).
2. **`locomotion.ts`:** `SEED_BIPED` + `tickLocomotion`. Локальный тест: один риг на клиенте, `moveGate='walk'`, `desiredYaw=0` → **идёт вперёд**. Тюним seed, пока не идёт стабильно (см. чеклист §11).
3. **Реакция на толчок:** биндим клик/выстрел → `applyImpulse` в торс → существо спотыкается и ловит себя (§2.4). Это первый «вау».
4. **`ga.ts`:** популяция + операторы (юнит-тесты на pure-операторах). Пока без сети — на клиенте-хосте: собираем live-fitness, каждые ~30 с показываем, что best идёт лучше.
5. **(05) сеть:** переносим авторитет существ на сервер, `world_snapshot` + `creature_genome`, GA-loop на сервере, клиент только рендерит (§6). Снимаем client-authoritative подпорку.
6. **Смерть → limp (§4)**, get-up (§2.5), персист best (§8.4).

### 9.2 MVP (Definition of Done)

- [ ] **Один биуед ХОДИТ** активным рэгдоллом из `SEED_BIPED` на 1-м кадре (не падает на ровном месте ≥30 с).
- [ ] Реагирует на толчок игрока: спотыкается, делает шаг, ловит баланс (или падает и встаёт).
- [ ] Смерть → плавно оседает в limp (passive-режим инкр.10).
- [ ] **Серверный GA-loop измеримо улучшает походку**: за сессию `bestOf().fitness` растёт, средняя скорость best-генома видимо выше, падений меньше. Владелец включает и **смотрит, как хорошеют**.
- [ ] Геном едет в снапшоте; конечности не синкаются; два клиента показывают консистентную «стилистику» ходьбы.
- [ ] Best-геном персистится между сессиями.

### 9.3 LATER (после MVP)

- Per-species эволюция (отдельные популяции biped/quadruped/blob).
- `SEED_QUADRUPED` (диагональная рысь: LF+RH в фазе, RF+LH в противофазе) и `SEED_BLOB` (радиальная пульсация/перекат — фаза как бегущая волна по «ногам»-выростам).
- Адаптация к рельефу (сэмпл высоты под стопой → подстройка `center` бедра; fitness на наклонной).
- Micro-sim ускоритель (§8.1-B).
- **Полный нейро-NEAT spike** (§10).

## 10. Опциональный поздний spike: нейро-NEAT (НЕ в этом инкременте)

Зафиксировано владельцем как «на потом». Заметка, чтобы не закрыть дорогу: заменить CPG-геном на маленькую сеть (входы: фаза, tilt, angVel, контакты стоп, desiredYaw; выходы: target-углы), эволюционируемую NEAT-ом (топология+веса). ## 11. Перф-бюджет и риски

### 11.1 Стоимость

- **PD-контроль:** `driveJoint` × суставы. Биуед ≈ 8 суставов + 3 балансовых момента ≈ **~11 дешёвых операций/кадр/существо** плюс сам solver суставов rapier (доминирует). Эмпирически держим **cap = 8 активно-шагающих существ** на клиенте (rapier joints — не бесплатны). Остальные — LOD.
- **LOD (по расстоянию до камеры):**
  - `near` (< 40 м): полный active-ragdoll.
  - `mid` (40–90 м): `tickProceduralPose` — гнём меши по CPG без физики суставов (кинематическая поза из того же генома, дёшево).
  - `far` (> 90 м) / за фрустумом: **frozen pose** или простой bob; root всё равно интерполируется.
  - `dead` далеко: заморозить limp через 3 с.
- **Сеть:** снапшот 15 Гц × (root+yaw+state+hp ≈ 6 float) × существа. Геном — редким каналом. Это порядок обычного player-updated трафика.
- **Сервер GA:** live-fitness ≈ бесплатен (метрики и так считаем). Micro-sim (если включат) — жёсткий `SIM_BUDGET_MS=2` бюджет, не стопорит тик.

### 11.2 Риски и митигции (честно)

| Риск | Реальность | Митигация |
|---|---|---|
| **Active-ragdoll баланс капризен в тюнинге** | Да, это самая нервная часть; легко получить «пьяного» ходока | Стартуем от **hand-tuned `SEED_BIPED`, который уже ходит**; GA только улучшает от рабочей точки, не с нуля. Клампы генов. Robust balance §2.4 (простой spring-to-upright, а не хрупкий inverse-dynamics). |
| **GA стохастичен, может выглядеть jank** | Да, отдельные геномы дёргаются | Элитизм (лучший ходок не теряется), штраф за энергию/tilt в fitness (jank наказывается), клампы, get-up-скрипт детерминирован. Показываем игроку **только best-known**, не сырых кандидатов. |
| **CPU сервера на эволюцию** | Умеренный при live-fitness; растёт при micro-sim | MVP без micro-sim. Бюджет `SIM_BUDGET_MS`. Пер-species популяции малы (24). |
| **Рассинхрон поз между клиентами** | Будет (ноги не синкаются) | By design допустимо (косметика). Синкаем genome+root, стиль совпадает; конкретный угол колена — нет, как debris. |
| **Взрыв моторов (нефизичная сила)** | Возможен при мутации gain/Kp | `TAU_MAX` кламп момента + `GENE_BOUNDS` кламп. |
| **10/05 не приехали** | Блокер | §0: MVP-2 (client-authoritative) заводит локомоцию+GA без сервера как временную демонстрацию; сеть подключается, когда 05 готов. |

## 13. Плейтестер-чеклист

**Локомоция (визуально):**
- [ ] Биуед стоит и НЕ падает сам ≥30 с (баланс живой).
- [ ] Идёт вперёд по `desiredHeading`, ноги в противофазе, колени подгибаются в переносе.
- [ ] Толкнул выстрелом → споткнулся, шагнул в сторону толчка, поймал себя (не «телепорт» и не мгновенное падение).
- [ ] Сильный толчок → упал → **встал** get-up-скриптом → пошёл дальше.
- [ ] Умер → плавно осел в limp (не выключился кадром, не остался стоять «звездой»).
- [ ] На дистанции переключается на дешёвую позу без заметного щелчка.

**GA (прогресс):**
- [ ] На старте сессии best-геном ходит «ок» (seed).
- [ ] Через ~5 мин best заметно **быстрее и стабильнее** (меньше падений, меньше дрожи).
- [ ] `bestOf().fitness` монотонно (в среднем) растёт по поколениям (лог/оверлей).
- [ ] Перезапуск сервера → существа стартуют с сохранённого best (не с сырого seed).
- [ ] Разные существа одного species визуально чуть разные (исследование живёт), но все ходят.

**Сеть:**
- [ ] Второй клиент видит те же существа в тех же root-позициях (интерполяция гладкая).
- [ ] Смена генома (новое поколение) применяется у всех клиентов (по `genomeRev`).
- [ ] Трафик существ ≈ порядок player-updated (геном не спамится каждый кадр).
- [ ] hp/смерть авторитетны на сервере (клиент не может «убить» локально).

## 14. Итог для владельца

Существа получают **тело, которое физически держит баланс и крутит цикл шага** (active-ragdoll), поэтому оно реагирует на пинки как живое, а не проигрывает клип. Поверх — **лёгкий GA на сервере**, который из поколения в поколение подкручивает параметры походки по fitness (уехал дальше, меньше падал, двигался плавнее). Стартуем с рабочего hand-seed (ходит сразу), а дальше владелец буквально **смотрит, как они учатся ходить лучше** — и прогресс сохраняется между сессиями. Никакого дорогого нейро-обучения: контролируемая цена, контролируемый риск, «живое» ощущение с первого кадра.
