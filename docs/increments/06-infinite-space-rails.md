## Часть A — БЕСКОНЕЧНЫЙ КОСМОС

## A1. Арт-дирекшн бесконечности (столпы)

1. **Нет края — есть рецессия.** Игрок никогда не видит «стену мира». Всё далёкое либо камеро-относительно (едет с игроком → никогда не достигается), либо тайлится/репитится вокруг него, либо тонет в слоёном тумане до того, как станет «плоским задником».
2. **Глубина через параллакс-слои.** Не один задник, а 3–4 оболочки на разных радиусах, движущиеся с разной «скоростью» относительно камеры → мозг читает бесконечный объём (принцип параллакса starfield-игр).
3. **Космос холодный, актор тёплый (свято).** Вся добавляемая бесконечность — в `VOID/UI_CYAN/ACCENT_VIOLET/BULL/BEAR`. Тёплые частоты (`ENEMY_AMBER/ALERT_RED/ACTOR_WHITE`) не трогаем — иначе далёкий скайлайн начнёт «спорить» с врагами за внимание.
4. **Дыхание, не дискотека.** Пульс грида, дрейф звёзд, свечение горизонта — амплитуды малы, периоды длинные (8–20 c). Психоделия медленная и величественная; целиться не мешает.
5. **Всё бесплатно по draw-call'ам.** Каждый слой бесконечности — 1 меш / 1 InstancedMesh / 1 Points. Бюджет всей части A: **≤ +6 draw-call'ов**, ноль аллокаций в `useFrame`.

## A2. Убрать жёсткие пределы (но оставить смерть)

**Проблема:** `y < -50 → gameOver` + пол-плоскость `1000×1000` на `y=-50` = дно ощущается близким. И `-50` совпадает с уровнем грида/нижних свечей → «низ мира» читается.

**Решение — оттолкнуть дно далеко вниз, сам kill оставить (иначе падение в никуда = баг):**
- `Player.tsx`: `KILL_Y = -300` (был `-50`). Вынести константой рядом с `JUMP_FORCE`:
  ```ts
  const KILL_Y = -300; // мир бесконечно проваливается; смерть — только когда реально улетел
  if (currentPos.y < KILL_Y) gameOver();
  ```
- Пол-плоскость в `Arena.tsx`: опустить на `y=-120` и оставить как **визуальный** «дальний дно-градиент», а не близкий пол. Он всё ещё `isFloor` (можно стоять, если долетел), но по факту это далёкий фон. Размер оставить `1000×1000` (в тумане края не видны).
- **Между** старым дном и новым kill добавить нижнюю дождь/звёзд-глубину (см. A3.3) → падать «в бездну данных», а не в «чёрный низ».

> Почему не убрать kill совсем: игрок-`RigidBody dynamic` с гравитацией `-30` будет падать вечно → `linvel` растёт, физика деградирует, а игрок «мёртв, но жив». Kill на `-300` = 3–4 c свободного падения сквозь красивую бездну, потом чистый respawn. Это фича, не баг.

**Down-raycast не трогаем** — он уже ищет `isFloor/isWall/isJumpPad`, дальний пол под этим подпадает.

## A3. Слои бесконечности (каждый: **что / как в R3F / перф-нота**)

Все три новых слоя собрать в один компонент `SpaceShells.tsx`, смонтировать в `Arena` рядом с `<MatrixRain/>`. Каждый слой — камеро-относителен там, где написано.

### A3.1 Камеро-относительный звёздный дрейф (parallax starfield)
**Что:** звёзды перестают быть куполом вокруг `(0,0,0)` и «едут» за камерой на большом радиусе, медленно вращаясь → никогда не достигаются, всегда окружают, дают самый дальний параллакс-слой.

**Как:**
- Оставить drei `<Stars>`, но **привязать его группу к камере по XZ** (не по Y — чтобы «верх/низ» космоса читался). В `useFrame`:
  ```tsx
  starsRef.current.position.set(camera.position.x, 0, camera.position.z);
  starsRef.current.rotation.y += dt * 0.006; // очень медленный дрейф
  ```
- Увеличить `radius` до `500`, `depth` до `200`, оставить `count=10000` (drei рисует их 1 `Points` — 1 draw-call). `fade` уже включён → близкие к границе гаснут, шва нет.
- Второй, **более близкий и более быстрый** слой звёзд (`radius=180, count=1500, factor=6`), тоже камеро-относительный, с чуть большей `rotation.y` скоростью → двухслойный параллакс = ощущение объёма.

**Перф:** 2 `Points`-меша, 2 draw-call'а, апдейт = 2 копирования вектора + 2 инкремента. Нулевые аллокации.

### A3.2 Многослойный MatrixRain (параллакс-дождь)
**Что:** сейчас 1 цилиндр `r=600` = видимая «труба». Делаем 3 концентрических оболочки на разных радиусах/скоростях/прозрачностях → дождь имеет глубину, а не читается как одна стена.

**Как (в `MatrixRain.tsx`, параметризовать существующий компонент):**
- Прокинуть props `radius`, `height`, `cols`, `speedMul`, `opacityMul`, `renderOrder`. Внутри — тот же шейдер, `uCols` = `cols`, а в фрагменте домножить альфу на `uOpacity`.
- В `SpaceShells` смонтировать три:
  ```tsx
  <MatrixRain radius={220} height={400} cols={60}  speedMul={1.4} opacityMul={1.0} renderOrder={-8}/>
  <MatrixRain radius={420} height={600} cols={90}  speedMul={1.0} opacityMul={0.7} renderOrder={-9}/>
  <MatrixRain radius={700} height={900} cols={140} speedMul={0.6} opacityMul={0.45} renderOrder={-10}/>
  ```
- **Все три — камеро-относительны по XZ** (`mesh.position.x/z = camera.x/z`) → игрок всегда в центре дождя, стену не догнать.
- Разные `radius+opacity+speed` = параллакс: близкий дождь быстрый и плотный, дальний — медленный бледный туман глифов.

**Перф:** 3 draw-call'а, стоимость шейдера фиксирована (процедурная в фрагменте, не зависит от `cols`-плотности). `depthWrite={false}`, `transparent`, сортировка через `renderOrder`. Апдейт = 3× copy XZ + инкремент `uTime`.

### A3.3 Нижняя бездна (down-shell) + горизонт-глоу
**Что:** чтобы «низ» не был чёрной дырой, добавить (а) слабое свечение-горизонт на уровне грида и (б) намёк на бесконечную глубину под ним.

**Как:**
- **Горизонт-глоу:** большое кольцо/диск `ringGeometry` (или градиентный `planeGeometry` billboard) на уровне `y≈-49`, `meshBasicMaterial` с радиальным градиент-текстуром (сгенерить `CanvasTexture` один раз: центр прозрачный → край `UI_CYAN`/`ACCENT_VIOLET` слабый), `toneMapped={false}`, `depthWrite={false}`, аддитивный blend. Bloom подхватит → «атмосфера над далёким дном». Камеро-относителен по XZ.
- **Down-shell:** перевёрнутый конус/полусфера-«воронка» под гридом (`coneGeometry`, BackSide, тёмный `VOID_DEEP` → `ACCENT_INDIGO` вертикальный градиент в вертекс-цветах), тоже камеро-относителен → падая, летишь сквозь сходящуюся к точке воронку данных, «дна» не видно.

**Перф:** 2 меша, 2 draw-call'а, статичные материалы. `CanvasTexture` создаётся 1 раз в `useMemo`.

### A3.4 Пульсирующий грид, тянущийся к CORE
**Что:** грид уже `infiniteGrid` (drei репитит его вокруг камеры бесплатно — краёв нет). Добавляем «дыхание» и направленность к центру → навигация + жизнь.
**Как:** drei `<Grid>` не даёт лёгкого доступа к своему шейдеру, поэтому дёшево — **пульсировать `fadeDistance`/цвет** нельзя напрямую. Вместо этого:
- Оставить `<Grid infiniteGrid/>` как есть (он и так бесконечен).
- Поверх — тонкий **аддитивный пульс-ринг** (расширяющееся кольцо `ringGeometry`, эмиссив `UI_CYAN`), эмитящийся из-под `CORE_EXCHANGE` раз в ~6 c, `scale` растёт 0→600, альфа гаснет. 1 меш, апдейт скейла/альфы в `useFrame`. Это «тик рынка прокатывается по бесконечному полу» — читаемый маяк центра + доказательство, что грид уходит вдаль.

**Перф:** 1 меш, 1 draw-call.

### A3.5 Рецессирующие неон-скайлайны (бесконечные свечные горизонты) — **later-tier, но заложить**
**Что:** чтобы горизонт был не пустым дождём, а силуэтом бесконечного города-графика: кольца далёких свечей-«башен», тайлящихся вокруг игрока, всегда на дистанции `~300–500`, тающих в тумане.
**Как (InstancedMesh, 1 draw-call на весь горизонт):**
- Детерминированно (seed) разложить `~200` тонких высоких боксов по кольцу `r∈[300,500]` вокруг центра, высоты по «графику» (broken-line из seed-шума).
- **Тайлинг вокруг игрока:** держать их относительными к камере крупными «чанками» (сдвигать всё кольцо на `round(camera/chunk)*chunk`), чтобы, куда бы игрок ни бежал, впереди всегда был скайлайн, но instance-матрицы не пересчитывались каждый кадр (только при пересечении границы чанка).
- Эмиссив `BULL/BEAR` тускло, `toneMapped={false}`, туман съедает дальние → бесконечный биржевой горизонт за 1 draw-call.
**Перф:** 1 InstancedMesh (200 инстансов), пересчёт матриц только на границе чанка (редко). В MVP можно пропустить (дождь+звёзды+горизонт-глоу уже дают бесконечность); включить, если владелец захочет «город».

## Часть B — ГИГАНТСКИЙ РЕЛЬС-СПЛАЙН (rollercoaster)

## B1. `src/game/spline.ts` — детерминированная кривая

**Задача:** один большой **замкнутый** CatmullRom-цикл с характером американских горок (перепады высот, банкинг на поворотах, минимум одна петля/штопор), охватывающий всю игровую зону (`±200+`) и взмывающий высоко (для чувства «внутри графиков»). **Детерминизм критичен:** все клиенты обязаны сгенерить БАЙТ-в-байт идентичную кривую из seed → поезд синхронизируется одним числом `t` с сервера, геометрию слать не надо (см. B5).

### B1.1 Дизайн контрольных точек (процедурно из seed)
**Подход:** не хардкодить точки руками (не масштабируется, не «горочно»), а **сгенерить их процедурно из фиксированного seed** детерминированным PRNG. Один seed → одна кривая навсегда.

```ts
import * as THREE from 'three';

// mulberry32 — крошечный детерминированный PRNG (одинаков на всех движках JS)
function mulberry32(seed: number) {
  return () => {
    seed |= 0; seed = (seed + 0x6D2B79F5) | 0;
    let t = Math.imul(seed ^ (seed >>> 15), 1 | seed);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

export const RAIL_SEED = 0x5EED_C0DE; // залочить — менять только осознанно, ломает синх со старыми клиентами

// Кольцо контрольных точек вокруг центра, с «горочными» вариациями высоты
function buildControlPoints(seed = RAIL_SEED): THREE.Vector3[] {
  const rnd = mulberry32(seed);
  const N = 14;                 // базовых узлов кольца (замкнём CatmullRom-ом)
  const R = 260;               // радиус охвата — шире арены (храмы на ±200)
  const pts: THREE.Vector3[] = [];
  for (let i = 0; i < N; i++) {
    const a = (i / N) * Math.PI * 2;
    const rr = R * (0.75 + rnd() * 0.5);            // «дышащий» радиус — не круг, а лепестки
    const x = Math.cos(a) * rr;
    const z = Math.sin(a) * rr;
    // высота-профиль горки: базовая волна + seed-джиттер, взлёты до ~140
    const baseY = 30 + Math.sin(a * 3) * 40;        // 3 «холма» на круг
    const y = baseY + rnd() * 60;                   // 30…170
    pts.push(new THREE.Vector3(x, y, z));
  }
  return pts;
}
```

**Петля/штопор (характер горки):** между двумя соседними узлами вставить готовый «петлевой» набор точек — вертикальный луп в плоскости движения:
```ts
function insertLoop(pts: THREE.Vector3[], afterIndex: number, radius = 45) {
  const a = pts[afterIndex], b = pts[(afterIndex + 1) % pts.length];
  const mid = a.clone().lerp(b, 0.5);
  const fwd = b.clone().sub(a).normalize();
  const up = new THREE.Vector3(0, 1, 0);
  const side = new THREE.Vector3().crossVectors(fwd, up).normalize();
  // 4 точки вертикального кольца (вход снизу → верх → выход)
  const loop = [0.15, 0.5, 0.85].map((k, i) => {
    const ang = k * Math.PI * 2;
    return mid.clone()
      .addScaledVector(fwd, (k - 0.5) * 30)
      .addScaledVector(up,  radius * (1 - Math.cos(ang)))   // взлёт
      .addScaledVector(side, radius * 0.25 * Math.sin(ang)); // лёгкий штопор вбок
  });
  pts.splice(afterIndex + 1, 0, ...loop);
}
```
Вызвать `insertLoop` на 1–2 детерминированных индексах (из того же PRNG) → гарантированная петля, одинаковая у всех.

### B1.2 Кривая + arc-length + helper API
```ts
export type RailPath = {
  curve: THREE.CatmullRomCurve3;
  length: number;
  getPoint: (t: number, out?: THREE.Vector3) => THREE.Vector3;      // t∈[0,1] по ДЛИНЕ (константная скорость)
  getTangent: (t: number, out?: THREE.Vector3) => THREE.Vector3;
  getUp: (t: number, out?: THREE.Vector3) => THREE.Vector3;         // стабильный «верх» для банкинга
  frames: { tangents: THREE.Vector3[]; normals: THREE.Vector3[]; binormals: THREE.Vector3[] };
};

export function buildRailPath(seed = RAIL_SEED): RailPath {
  const points = buildControlPoints(seed);
  insertLoop(points, 4);          // детерминированные индексы
  insertLoop(points, 9);
  const curve = new THREE.CatmullRomCurve3(points, /*closed*/ true, 'catmullrom', /*tension*/ 0.5);

  // Frenet-каркас: три.js даёт стабильные нормали/бинормали вдоль всей кривой
  const SEG = 800;                                       // разрешение семплирования
  const frames = curve.computeFrenetFrames(SEG, /*closed*/ true);

  // Arc-length LUT для КОНСТАНТНОЙ скорости (u = равномерно по длине, а не по параметру)
  curve.arcLengthDivisions = SEG;
  const length = curve.getLength();

  const getPoint = (t: number, out = new THREE.Vector3()) =>
    curve.getPointAt(THREE.MathUtils.euclideanModulo(t, 1), out);   // getPointAt = arc-length параметр
  const getTangent = (t: number, out = new THREE.Vector3()) =>
    curve.getTangentAt(THREE.MathUtils.euclideanModulo(t, 1), out).normalize();
  const getUp = (t: number, out = new THREE.Vector3()) => {
    const i = Math.floor(THREE.MathUtils.euclideanModulo(t, 1) * SEG) % SEG;
    return out.copy(frames.normals[i]);                 // стабильный up для банкинга вагона
  };

  return { curve, length, getPoint, getTangent, getUp, frames };
}
```

**Ключевые решения и почему:**
- **`getPointAt`/`getTangentAt` (arc-length), не `getPoint`/`getTangent` (raw param).** CatmullRom по «сырому» `t` идёт неравномерно (в поворотах медленнее). Arc-length LUT (`arcLengthDivisions`) выравнивает → поезд поедет с **константной скоростью**, что и нужно для сети (`t` от сервера линеен по времени).
- **`computeFrenetFrames(closed=true)`** даёт стабильную тройку (tangent/normal/binormal) по всей кривой без «переворота» на петле — это и есть **up-вектор для банкинга**. Frenet может слегка крутиться на прямых, но для замкнутой горки это как раз «наклон в вираж» — то, что нужно.
- **`euclideanModulo(t,1)`** — `t` от сервера может быть `>1` (накопленный прогресс); заворачиваем в `[0,1]` → бесконечная езда по циклу.
- **Детерминизм:** `mulberry32` + фикс `RAIL_SEED` + фикс `N/SEG/tension/closed`. Никаких `Math.random()`. Любой клиент из того же seed получит идентичные `points` → идентичную `curve` → идентичные `frames`. Проверяемо (см. B6 чек-лист).

**Как семплировать (для рендера / для поезда):**
```ts
const rail = buildRailPath();
const p = rail.getPoint(t, _tmpPos);       // позиция вагона
const tan = rail.getTangent(t, _tmpTan);   // куда смотрит (lookAt p+tan)
const up = rail.getUp(t, _tmpUp);          // банкинг (наклон)
// матрица вагона: makeBasis(side, up, -tan) либо object.up=up; object.lookAt(p+tan)
```

## B2. `RailTrack.tsx` — визуальные рельсы (дёшево)

**Что:** сама горка как светящаяся неон-лента сквозь весь космос. Bloom обязан её ловить.

**Метод (MVP) — `TubeGeometry` из кривой, 1 меш = 1 draw-call:**
```tsx
import * as THREE from 'three';
import { useMemo } from 'react';
import { buildRailPath } from '../game/spline';
import { PALETTE } from '../theme';

export const RailTrack = () => {
  const geo = useMemo(() => {
    const { curve } = buildRailPath();
    // tubularSegments высокий (гладкая петля), radius маленький (тонкий рельс), radialSegments низкий
    return new THREE.TubeGeometry(curve, 800, 1.4, 6, /*closed*/ true);
  }, []);

  return (
    <mesh geometry={geo} renderOrder={-1}>
      <meshStandardMaterial
        color={PALETTE.uiCyan}
        emissive={PALETTE.uiCyan}
        emissiveIntensity={1.4}
        roughness={0.3}
        metalness={0.8}
        toneMapped={false}          // ← без этого Bloom не возьмёт неон в пересвет
      />
    </mesh>
  );
};
```

**Детализация «две рельсы + шпалы» (still cheap):**
- **Две нити:** сгенерить второй `TubeGeometry` со смещением каждой точки на `±side*gauge/2` (`side = tangent × up`), либо просто вторая труба с чуть большим радиусом (визуально «двойной рельс»). +1 draw-call.
- **Шпалы (sleepers) + маркеры скорости — `InstancedMesh`, 1 draw-call на ВСЕ шпалы:**
  ```ts
  const COUNT = 240;
  const inst = new THREE.InstancedMesh(boxGeo, sleeperMat, COUNT);
  const m = new THREE.Matrix4(), q = new THREE.Quaternion();
  for (let i = 0; i < COUNT; i++) {
    const t = i / COUNT;
    rail.getPoint(t, _p); rail.getTangent(t, _tan); rail.getUp(t, _up);
    _side.crossVectors(_tan, _up).normalize();
    q.setFromRotationMatrix(_basis.makeBasis(_side, _up, _tan.clone().negate()));
    m.compose(_p, q, _scale);      // плоская «шпала» поперёк рельса
    inst.setMatrixAt(i, m);
  }
  inst.instanceMatrix.needsUpdate = true;
  ```
  Каждая ~8-я шпала — ярче (`BULL_HOT`) как **маркер скорости**: когда поезд поедет, они замелькают → читаемая скорость. Цвет шпал через `instanceColor` (тот же 1 draw-call).

**Цвет/палитра:** основная лента `UI_CYAN` (цвет «данных», холодная — не спорит с акторами). Акценты петель — `ACCENT_VIOLET`. Маркеры скорости — `BULL_HOT`. Никакого тёплого набора.

**Перф-нота:** MVP = **1 draw-call** (одна труба). Полный вариант = **3–4 draw-call'а** (2 нити + шпалы-instanced + маркеры через instanceColor). `TubeGeometry(800,·,6,·)` ≈ 800·6·2 ≈ 9.6k tris — копейки. Геометрия строится 1 раз в `useMemo`, в `useFrame` рельс статичен (0 стоимости) — движется только поезд (след. инкремент).

## B3. Коллизия / взаимодействие (позиция на сейчас)

- **MVP: рельс чисто визуальный + путь.** Никаких коллайдеров. `TubeGeometry`/instanced-шпалы — просто меши без `RigidBody`. Поезд поедет по кривой кинематически (след. инкремент), физически ни с чем не сталкиваясь (или лёгкий триггер-урон при контакте — решим тогда).
- **Ходить/стоять по рельсам? — optional, later.** Если владелец захочет «беги по горке» — дать шпалам `userData.isFloor` и тонкий `RigidBody type="fixed"` с `TrimeshCollider` из той же геометрии, либо (дёшево) редкие box-коллайдеры-«площадки» на плоских участках. В MVP **не** делаем: trimesh из 800-сегментной трубы = дорогой коллайдер, а горка задумана как объект любования/путь поезда, не как платформинг. Down-raycast игрока трогать не надо.
- **Не мешать движению игрока:** рельс проходит высоко (`y` до ~170) и по кольцу `r≈260` — вне основных боевых путей (`±200`), так что визуально величествен, но не загораживает бой.

## B5. Сеть: детерминизм = ноль синка геометрии

- Сплайн **не сериализуется и не шлётся**. Каждый клиент вызывает `buildRailPath(RAIL_SEED)` → получает идентичную кривую (см. B1: фикс seed + PRNG + фикс параметры, ноль `Math.random`).
- Поезд (инкремент 7) получает от сервера **только `t`** (число `[0,1)`, прогресс по arc-length). Клиент делает `rail.getPoint(t)` / `getTangent` / `getUp` → позиция/ориентация/банкинг. Это стыкуется с сетевым бэкбоном из **05-net-world-backbone** (сервер тикает мировое время/прогресс, клиенты интерполируют).
- Поскольку `t` — по **arc-length** (константная скорость), серверу достаточно слать `t = (worldTime * speed / rail.length) % 1` или даже просто `worldTime` + договорённая `speed` → каждый клиент вычислит `t` сам, вообще без пер-кадрового трафика на поезд. Идеальный детерминированный объект.
- **Инвариант:** `RAIL_SEED` и параметры (`N`, `SEG`, `tension`, `closed`, петлевые индексы) — часть «мирового контракта». Менять только версионируя мир, иначе клиент со старым seed увидит поезд «рядом с рельсом». Залочить рядом с сетевыми константами.

## B6. Тюнинг-ручки + чек-лист

### Vibe / perf чек-лист (для человека-плейтеста)
- [ ] Кручусь на месте — **нигде не видно «края мира»/стены** (дождь/звёзды едут за мной, туман съедает дальнее).
- [ ] Есть ощущение **глубины/параллакса**: близкий дождь быстрее дальнего, звёзды дрейфуют слоями.
- [ ] Прыгнул в пропасть — падаю **сквозь красивую бездну данных**, не в чёрный низ; смерть наступает не сразу (`~3 c`).
- [ ] **Горка видна издалека**, светится (Bloom), читается как исполинский awe-объект «внутри графиков», петли на месте.
- [ ] Рельс **не загораживает бой** и не спорит по цвету с врагами (актор тёплый — рельс холодный).
- [ ] Пульс-ринг из центра «дышит» медленно, не раздражает, помогает найти CORE.
- [ ] **60 fps** держится (dpr, туман, draw-calls); в консоли/`r3f` draw-calls выросли лишь на ~6–10.
- [ ] (Детерминизм) В двух вкладках/клиентах рельс **в одном и том же месте** — визуально идентичен.

- `KILL_Y=-300` + опущенный дальний пол → мир проваливается, смерть сохранена.

- Итог: **бесконечный космос без краёв + видимая, светящаяся, катаемая (готовая под поезд) горка**, +6–10 draw-calls, 60 fps.
