## 1. Арт-дирекшн: столпы + залоченная палитра

### 1.1 Пять столпов (locked)
1. **Ты ВНУТРИ графика, не смотришь на него.** Свечи — это архитектура, по которой дерёшься; тикеры летят СКВОЗЬ тебя; дождь падает вокруг. Мир окружает, а не декорирует задник.
2. **Свет = эмиссия, тьма = объём.** Почти нет реальных источников света. Всё, что «светится», светится потому что `emissive` + **bloom**. Тьма между неоном даёт глубину и делает силуэты бойцов читаемыми.
3. **Всё живо и дышит.** Ни один крупный элемент не статичен: свечи микро-пульсируют/растут, тикеры ползут, дождь течёт, грид пульсирует к `CORE_EXCHANGE`. Но амплитуды МАЛЫ — «дыхание», не «дискотека», чтобы не тошнило и не мешало целиться.
4. **Хаос организован в потоки.** Психоделия направленная: частицы, тикеры и свет тяготеют К ЦЕНТРУ (`CORE_EXCHANGE`) — арена читается как воронка/сердце рынка. Направление = встроенная навигация.
5. **Читаемость боя — священна (см. §5).** Мир играет в холодных сине-фиолетово-мятных тонах; бойцы/снаряды/враги — в тёплых (амбер/белый/красный-тревога), которых в мире почти нет. Юмор джуса никогда не крадёт кадр у противника.

## 2. Сигнатурные элементы мира (добавить / поднять)

Каждый пункт: **что**, **как в three/R3F**, **перф-нота**.

### 2.1 Живые свечи как АРХИТЕКТУРА (upgrade `Candlestick`)
**Что:** свечи перестают быть статичными боксами — они дышат и медленно «торгуются», формируя ridge-line / скайлайн, вокруг которого дерёшься. Коллайдер (`RigidBody type="fixed"`, `boxGeometry`) **остаётся фиксированным** — двигается только визуальный меш/скейл в пределах ±5–8%, чтобы не рассинхронить физику.

**Как:**
- Материал свечи-платформы: `meshStandardMaterial` → добавить `emissive={color}`, `emissiveIntensity` анимируемый `0.4…0.9`, `toneMapped={false}` (чтобы bloom взял неон в пересвет), `roughness 0.35 metalness 0.7`.
- «Дыхание»: в `useFrame` гонять `emissiveIntensity` синусом с фазой от позиции: `0.6 + 0.3*Math.sin(t*breatheSpeed + phase)`. Фаза = `(position.x + position.z)*0.05` → соседние свечи пульсируют волной (эффект «прокатывающегося тика по рынку»).
- Фитиль: `meshBasicMaterial` → оставить basic (дёшево, всегда fullbright), но `toneMapped={false}` + кончик подсветить `BULL_HOT/BEAR_HOT` через второй тонкий цилиндр сверху.
- **Инстансинг (важно):** сейчас ~90 свечей = 90 `RigidBody` + 90 меша + 90 фитилей = сотни draw-call'ов. Разделить на:
  - **Коллайдеры** — оставить индивидуальными `RigidBody` (Rapier это ест нормально, они fixed).
  - **Визуал** — перевести тела свечей в `<Instances>`/`<InstancedMesh>` drei: один draw-call на все бычьи, один на все медвежьи (разбивка по цвету, т.к. `emissive` в атрибут инстанса сложнее). Пульсацию гнать через `instanceMatrix` scale.y или через `instanceColor`.
- «Ridge-line skyline»: сгруппировать высоты по путям так, чтобы силуэт читался как биржевой график (уже почти так в `addCandles` — усилить: сделать высоты не рандомными, а по синусоиде тренда + шум, чтобы был «профиль свечного графика»).

**Перф-нота:** инстансинг тел свечей = **−150…250 draw-call'ов**. Пульсация — чистая мутация атрибутов, без аллокаций в `useFrame` (заранее выделить `dummy = new THREE.Object3D()`). Бюджет: <0.3 ms/кадр.

### 2.2 Матрица «цифровой дождь» (новый `MatrixRain`)
**Что:** падающие колонки зелёно-цианового глифо-дождя как окружающий задник + опционально ближние «шторы» дождя, сквозь которые видно арену. Ключевой psychedelic-сигнал «ты в матрице».

**Как — три метода, от дешёвого к дорогому. Рекомендую METHOD A (шейдер на изогнутом заднике) как основной, B — если нужен объём.**

**METHOD A (рекомендовано) — GLSL на одной большой цилиндр/сфер-оболочке (skyshell).**
Один меш, один материал, весь дождь — процедурный в фрагментном шейдере. ~1 draw-call, нет геометрии глифов.

```glsl
// fragment (ShaderMaterial), backSide, depthWrite:false, toneMapped:false
uniform float uTime;
uniform vec3  uColor;     // UI_CYAN #4cc9f0
uniform vec3  uColorHot;  // BLOOM_WHITE кончик капли
varying vec2  vUv;

float hash(vec2 p){ return fract(sin(dot(p, vec2(127.1,311.7)))*43758.5453); }

void main(){
  // колонки по горизонтали
  float cols = 90.0;
  vec2 uv = vUv * vec2(cols, 1.0);
  float col = floor(uv.x);
  float speed = 0.3 + 0.7*hash(vec2(col, 1.0));       // разная скорость колонок
  float y = fract(uv.y * 18.0);                        // «символы» по вертикали
  float head = fract(uv.y - uTime*speed);              // позиция головы капли
  float glyph = step(0.5, hash(vec2(col, floor(uv.y*18.0 + uTime*speed*18.0)))); // мерцание символа
  float trail = smoothstep(0.0, 0.25, head) * (1.0-head); // хвост-затухание
  float bright = glyph * trail;
  vec3 col3 = mix(uColor, uColorHot, pow(1.0-head, 8.0)); // белая голова капли
  float alpha = bright * 0.9;
  gl_FragColor = vec4(col3 * bright, alpha);
}
```
- В R3F: `<mesh><cylinderGeometry args={[600,600,700,64,1,true]}/><shaderMaterial ... transparent side={THREE.BackSide} depthWrite={false}/></mesh>`, обёрнутый вокруг арены. `uTime` тикать в `useFrame`.
- Это ЗАМЕНЯ­ЕТ/дополняет `<Stars>` как фон — дождь читается на дальнем плане, звёзды можно оставить тусклее (`factor 3`) или убрать.

**METHOD B — ближние «шторы» дождя из `<Instances>` спрайтов (для объёма/паралакса).**
2–4 плоскости-билборда ближе к игроку с тем же шейдером, `alpha` ниже → паралакс-дождь на переднем плане. Держать на большом расстоянии от боевых поверхностей, чтобы не мешал прицелу.

**METHOD C (НЕ рекомендую как основной) — реальные глифы `InstancedMesh` + текстур-атлас катаканы.** Дорого (тысячи инстансов), даёт мало сверх шейдера. Только если владелец захочет «настоящие символы вблизи».

**Перф-нота:** METHOD A — 1 draw-call, вся работа на GPU, фикс-стоимость ~0.2–0.4 ms независимо от «плотности». Идеально для веб-60fps. Low-preset: уменьшить `cols` до 40 и убрать METHOD B.

### 2.3 Тикер-ленты / летящие ценовые глифы / поток ордербука (новый `TickerStreams`)
**Что:** горизонтальные светящиеся ленты «`BTC ▲ 64,201  ETH ▼ 3,410  …`», ползущие вокруг храмов и вдоль путей; редкие «летящие числа», уносящиеся к центру. Амбиентное движение = мир живёт.

**Как:**
- **Текст — осторожно с перфом.** drei `<Text>` (troika) хорош, но каждая надпись = свой меш/SDF-атлас; десятки живых `<Text>` с меняющимся содержимым = дорого (перегенерация геометрии). Правила:
  - Содержимое тикеров **не меняем каждый кадр** — генерим строку раз, двигаем как единый объект (`position.x -= speed*dt`, зациклить). Мутация transform дёшева, мутация текста — нет.
  - Ограничить 8–16 живых тикер-лент. Использовать `<Text characters="0123456789.,%▲▼ABCDEFGHIJKLMNOPQRSTUVWXYZ ">` чтобы предзагрузить атлас глифов.
  - `material-toneMapped={false}`, цвет `UI_CYAN`/`BULL`/`BEAR` (зелёный для ▲, розовый для ▼).
- **Дешёвая альтернатива для дальних лент:** канвас-текстура (нарисовать строку в `CanvasTexture` один раз) на тонком `planeGeometry`, скроллить `map.offset.x` в `useFrame` — 1 draw-call на ленту, текст «бежит» через `offset`. Рекомендую этот метод для фоновых лент, `<Text>` — только для 2–3 ближних «геройских».
- **Летящие числа к центру:** пул из ~30 `<Text>`/спрайтов, каждый `lerp`-ит к `CORE_EXCHANGE` и растворяется (`opacity→0`), затем респавн с новым числом. Переиспользовать объекты (пул), без создания/удаления в рантайме.

**Перф-нота:** канвас-текстур-ленты ~1 draw-call каждая, троика-`<Text>` держать ≤16. Никакой перегенерации SDF в `useFrame`. Бюджет: <0.5 ms.

### 2.4 Объёмный неон-грид / свечение горизонта / fog + скайбокс
**Что:** глубина и «бесконечность потока». Дальний край растворяется в дымке цвета войда, у горизонта — тлеющее неон-зарево; грид пульсирует волной к центру.

**Как:**
- **Fog:** добавить `<fog attach="fog" args={['#02020a', 150, 650]}/>` (или `fogExp2`) на сцену — далёкие свечи/тикеры тают → мгновенная глубина + скрывает поп-ин инстансов. Цвет = `VOID_DEEP`.
- **Скайбокс/градиент-энв:** вместо чистого чёрного — вертикальный градиент `VOID_DEEP`(верх) → лёгкое `ACCENT_INDIGO`-зарево у горизонта. Дёшево: большая `sphereGeometry` `BackSide` с `shaderMaterial` градиентом ИЛИ drei `<Environment>` c preset/собственной градиент-текстурой (для рефлексов на metalness-свечах — бонус к «дорогому» виду).
- **Грид (upgrade `<Grid>`):** оставить drei `<Grid>`, но:
  - Приглушить `cellColor` до `GRID_CELL #1a2140`, `sectionColor` `GRID_SECT #4a2c73`.
  - Пустить **пульс-волну** к центру: либо `<Grid>`-проп `fadeDistance` + анимировать через собственный шейдер-грид (radial pulse `sin(dist - t)`), либо наложить второй тонкий кастом-грид-шейдер с бегущим кольцом свечения от `CORE_EXCHANGE`. MVP-вариант: анимировать `sectionColor` дыханием (мелко).
- **Горизонт-зарево:** тонкое эмиссивное кольцо/диск под ареной у линии `y≈-49`, цвет `BEAR/NODE`, ловится bloom'ом → «свет из-под мира».

**Перф-нота:** fog — бесплатно. Скайбокс-градиент — 1 draw-call. Радиальный пульс-грид на шейдере — 1 draw-call. Всё копеечное, эффект «дорогой».

### 2.5 Потоки «flux» — частицы к `CORE_EXCHANGE` (новый `DataFlux`)
**Что:** реки светящихся частиц/битов данных, текущие по путям-свечам ВНУТРЬ к центру — визуализируют «капитал стекается в ядро», усиливают воронку и навигацию.

**Как:**
- Один `<Points>` / `THREE.Points` с `~2000–4000` точек, `AdditiveBlending`, `sizeAttenuation`, цвет `UI_CYAN`/`BULL`, `toneMapped={false}`.
- Движение: в `useFrame` каждую точку двигать вдоль её пути к центру (`pos += dir*speed*dt`), при достижении ядра — респавн у внешнего нода. Пути = те же 4 диагонали, что в `addCandles`. Хранить позиции/скорости в `Float32Array`, мутировать `geometry.attributes.position`, `needsUpdate=true`. **Ноль аллокаций в кадре.**
- Альтернатива дешевле: GPU-particles через шейдер (позиция = функция времени `mod`), тогда CPU вообще не трогает точки. Рекомендую CPU-версию для MVP (проще), GPU — если профайлер покажет затык.
- Бонус: у самого `CORE_EXCHANGE` — восходящий «столб данных» (тонкий цилиндр-шейдер с бегущими вверх штрихами) → ядро視уально «всасывает и выстреливает» поток.

**Перф-нота:** 1 `<Points>` = 1 draw-call на все частицы. 3–4k точек с CPU-апдейтом ~0.3–0.5 ms. Low-preset: 1000 точек.

## 3. Пост-процессинг (стек `@react-three/postprocessing`)

> **Зависимость:** `@react-three/postprocessing` (и его пир `postprocessing`) **НЕ установлен** — добавить:
> `npm i @react-three/postprocessing postprocessing`. Обернуть эффекты в `<EffectComposer>` внутри `<Canvas>` (см. §7). Это **ядро** увода мира в «дорого» — без bloom весь неон/эмиссия не светятся.

Новый компонент `PostFX` в `Game.tsx`, ставится ПОСЛЕ сцены внутри `<Canvas>`:

| Пасс | Параметры (High) | Роль | Заметка |
|---|---|---|---|
| **Bloom** (Selective/Unreal-style) | `intensity 1.1`, `luminanceThreshold 0.15`, `luminanceSmoothing 0.9`, `mipmapBlur`, `radius 0.7` | сердце вида: неон/эмиссия расцветают | нужен `toneMapped={false}` на эмиссивных материалах, иначе порог не берёт |
| **Vignette** | `offset 0.25`, `darkness 0.75`, `eskil={false}` | фокус в центр, «тоннель», глубина | дёшево |
| **ChromaticAberration** | `offset [0.0006, 0.0009]` (мелко!) | лёгкая цифровая расфокусировка по краям | не переборщить — тошнит и бьёт по читаемости |
| **Scanline / Noise** | `Scanline density 1.1 opacity 0.06` + `Noise opacity 0.03 premultiply` | CRT/матрица-текстура, «сигнал» | очень тонко, фон-текстура |
| **Glitch** (по событию) | `mode GlitchMode.SPORADIC`, `duration [0.1,0.2]`, включать импульсно | psychedelic-«хиты»: при смерти/крупном хите/смене mood | НЕ постоянно — только вспышками, иначе укачивает и ломает бой |
| **SMAA** | по умолчанию | сглаживание (на канвасе `antialias:false`, MSAA нет) | дешевле MSAA, чинит «лесенку» неона |
| **ToneMapping** | `ACESFilmic` | приятный роллофф пересветов bloom | drei/`<EffectComposer>` управляет |

**Порядок пассов:** Bloom → ChromaticAberration → Scanline/Noise → Vignette → (Glitch импульсно) → SMAA (последним).

**Бюджет 60 fps и fallback (low-preset).** Целимся ≤3–4 ms на весь composer при 1080p.
- **High (desktop, dpr≤1.5):** весь стек выше, Bloom `mipmapBlur`.
- **Medium:** Bloom (`intensity 0.9`, без `mipmapBlur` radius↓) + Vignette + SMAA. Без хроматики/сканлайна/glitch.
- **Low (слабое GPU / fps<50):** **только Bloom** (`intensity 0.7`, KernelSize.SMALL) + Vignette. Матрица-дождь `cols 40`, flux 1000 точек, тикеры-канвас вместо `<Text>`.
- Автопресет: следить за fps (drei `<PerformanceMonitor>` или свой EMA по `delta`); падение <50 fps на N секунд → спуск пресета (уменьшить `Bloom.intensity`, отключить хроматику/сканлайн, срезать частицы). Хранить `qualityTier` в zustand, читать в PostFX/эффектах.

## 4. Свет и настроение

- **Эмиссия-first.** Оставить `ambientLight ~0.15–0.2` (чтобы неэмиссивные грани бойцов/врагов не были чёрными) + один слабый `directionalLight ~0.5–0.8` для мягкого объёма силуэтов. **Весь «свет мира» — это `emissive` + bloom**, а не лампы. Так неон «горит» в тёмной сцене, а тьма между ним = глубина.
- **`toneMapped={false}`** на всех неон-материалах (свечи, jump-pad, ядро, тикеры, дождь, flux) — критично: только тогда их яркость превышает `luminanceThreshold` bloom'а и они реально светятся, а не просто «цветные».
- **`CORE_EXCHANGE`** — самый яркий объект сцены (`emissiveIntensity 1.2–1.6`, `BEAR`→ядро `BLOOM_WHITE`), визуальный магнит/навигатор. Внешние `NODE_*` — вторичные маяки (`NODE` синий, `emissiveIntensity 0.8`).
- **Mood-сдвиги «market open/close» (опциональный флейвор, новый `WorldMood`):**
  - **BULL RUN:** доминанта `BULL`/`DATA_EMERALD`, grid-пульс быстрее, flux ярче, скайбокс-зарево зеленее. 
  - **BEAR / CRASH:** доминанта `BEAR`, редкие Glitch-импульсы, дождь плотнее, зарево красное, свечи чаще «красные».
  - **CALM / NIGHT:** приглушённый неон, медленный дождь, тише flux.
  - Реализация: `WorldMood` держит `moodTier` в zustand + `lerp` глобальных множителей (bloomIntensity, rainDensity, fluxSpeed, tintColor), которые читают материалы/PostFX. Переключать по таймеру раунда/событию сервера (косметика, не влияет на геймплей → сеть-безопасно). MVP: не обязателен, но крючки заложить.

## 5. Читаемость боя (священное правило)

Психоделия НЕ должна мешать видеть врага/снаряд/себя. Правила силуэта и контраста:

1. **Разделение частот цвета (главное).** Мир = холодные сине-фиолетово-мятные + цианит данных. Акторы = тёплые/тревожные: враги `ENEMY_AMBER #ffb703`, урон/трейсеры `ALERT_RED`, вспышки/хитмаркеры `ACTOR_WHITE`. Эти три цвета мир крупно НЕ использует → глаз мгновенно вычленяет геймплей из фона.
2. **Rim / силуэт на акторах.** Дать врагам/удалённым игрокам лёгкий эмиссивный rim (Fresnel-подсветка контура), чтобы они не сливались с неоновой стеной. Даже слабый rim `ENEMY_AMBER` читается сквозь bloom.
3. **Bloom не трогает акторов сверх меры.** `luminanceThreshold 0.15` + держать эмиссию акторов НИЖЕ порога размытия ядра (или использовать Selective Bloom с layer'ами: bloom-слой только для мира). Иначе враг «расплывается» и теряет край. Рекомендация: **Selective Bloom** — назначить `layer 1` мировым эмиссивам, композитить bloom только по нему; акторы остаются резкими.
4. **Снаряды всегда ярче фона + собственный трейсер.** Трейсеры `ALERT_RED`/`ACTOR_WHITE`, `AdditiveBlending`, `toneMapped={false}` — гарантированно поверх любого дождя.
5. **«Чистая зона» вокруг боевых поверхностей.** Матрица-METHOD B (ближние шторы) и flux НЕ проходят сквозь плоскости, где стоят бойцы: держать частицы над/под уровнем боя или прозрачными вблизи камеры. Дождь-METHOD A — только дальний задник.
6. **Хроматика/сканлайн/noise — микро-дозы** (см. §3): край экрана, не центр; постоянная сила низкая; Glitch — только импульсами по событию, не фоном.
7. **Тест-критерий:** на любом кадре силуэт врага и линия снаряда должны читаться за <200 мс. Если владелец «теряет» врага в кадре — снижаем bloom `intensity`/поднимаем rim/уводим фон холоднее. Читаемость > красота, всегда.

## 6. Амбиентное аудио (направление; реализация — не здесь)

Привязка к `src/utils/audio.ts` (сейчас: WebAudio `AudioContext`, `playShootSound` square-осц, `playJumpSound` sine-свип; **амбиент-бэда нет**). Направление для будущего `startAmbientBed()`:

- **Market-hum bed (основа):** низкий тёплый дрон-пэд (2–3 детюненных `sawtooth`/`triangle` осциллятора ~55–110 Гц + медленный LFO на фильтр) → «гул торгового зала / машинного зала матрицы». Тихо, зациклено, без атаки.
- **Data-blips (амбиент-жизнь):** редкие короткие sine/triangle «пинги» (800–2000 Гц, 40–80 мс, лёгкий delay) в псевдослучайном ритме — «сделки проходят». Стерео-пан рандомный → пространство. Плотность блипов = функция `moodTier` (BULL RUN → чаще/выше, CALM → реже).
- **Low drone / под-порог:** суб-бас `sine` ~35–45 Гц, очень тихо, для «трепета/масштаба» (ощущение бездны под ареной).
- **Реактивность на mood:** при BEAR/CRASH — дрон детюнится вниз, добавить лёгкий шум/дисторшн; при Glitch-импульсе — короткий bitcrush/шум-всплеск в синхрон с визуальным glitch.
- **Микс:** bed ≪ SFX выстрелов/попаданий — амбиент не должен маскировать боевые звуки (тот же принцип, что §5 для картинки). Мастер-гейн бэда ~0.05–0.1.
- Всё — процедурно на существующем `AudioContext` (без ассетов-файлов), в духе уже написанных функций.

## 9. MVP инкремента 3 (минимум, что МГНОВЕННО меняет вайб)

**MVP = Ф1 + Ф2-lite:**
